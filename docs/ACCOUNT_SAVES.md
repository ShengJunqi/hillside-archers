# 账号与云存档

游戏仍可直接本机游玩。旅营与暂停菜单提供可选的「账号与云存档」；使用已购的 CloudBase 国内站上海个人版环境，PostgreSQL 存储永久进度。账号服务独立于两个静态网站，同一账号可读取同一份云存档。

## 玩家流程

- 日常只用账号和密码登录，也兼容已有邮箱账号。自助注册时验证一次邮箱，并设置 3–24 位账号及 8–32 位密码；CloudBase 不支持客户端仅凭用户名密码完成注册。密码及令牌交给官方 SDK，不写入游戏存档。
- 未登录的本机游客不创建 CloudBase 匿名身份。新游客启动游戏不请求云服务，注册或登录也不清空本机进度。
- 第一次关联账号时，在旅营确认上传本机进度，或选择云端修行与余烬。切换账号也需要明确选择。
- 后续永久进度改变后约两秒同步；断网或云端报错时保留本机存档，显示待重试。重新联网、回到旅营或窗口重新获得焦点时检查同步。
- 云端更新只在旅营应用，不改变进行中的对局、生命、遗物或随机状态。退出账号继续保留本机进度。
- 手机、电脑与不同网址使用同一账号服务；它们各自保存 SDK 会话，不自动共享 localStorage。

## 存档与冲突

兼容原有 `hillside-archers-save-v2` 和 `HA2:` 迁移码，同步章节、解锁、纪录、弓手名字、余烬与永久修行，不包含当前远征的临时构筑。

纪录、章节与解锁可合并；**余烬余额、练弓等级、强身等级必须整组选择**，不能分别取最大值或相加余额。两个设备从同一修订同时写入，只有一份被接受，另一份停下来让玩家选择。进行中的对局不能选择或替换进度。

每次覆盖本机进度前保存备份，最多保留四份。弹窗可查看最近备份的迁移码，复制后从「迁移进度」导入。迁移码仍是离线备份工具，不作为自动同步协议。

同步元数据单独保存在 `hillside-archers-cloud-v1`，包含账号 UID、上次修订、基线与待确认请求。请求 ID 在联网前保存；服务器已提交但回包丢失时，重试同一 ID，不重复增加修订或重复结算。请求期间新获得的进度使用下一次修订上传。

这是个人进度存档，不是用于排行榜、付费货币或多人对战的反作弊服务器。未来竞争性结果需要服务器计算与验证。

## 服务器与权限

版本化 SQL 位于 `cloudbase/migrations/`，已应用两份迁移：

- `20261109165200_player_cloud_saves`：`public.archer_saves` 表、按 `auth.uid()` 隔离的 SELECT RLS、原子修订检查与请求去重。
- `20261109170600_guard_save_account`：对外 RPC `archer_save_for_account` 在事务内再次核对 `expected_owner`，防止切换账号时旧请求写入新账号；撤销客户端对内部 RPC 的执行权限。

表的 owner 为 text，匹配 CloudBase 的 `auth.uid()`。匿名角色不能读取；登录用户只能读取自己的行，不能直接 INSERT/UPDATE/DELETE，写入必须经过 RPC。RPC 校验真实登录、非匿名身份、字段范围与版本；前端不能指定实际存储的 owner，也不能跳过修订检查。

## 本地开发与发布

普通游戏开发仍只需要 Node.js 22+，无需 npm 安装依赖。CloudBase 官方浏览器 SDK 3.11.0 附在 `dist/vendor/`，按需加载；许可证随源码保留。`dist/cloud-client.mjs` 维护唯一 SDK 客户端，`cloud-save.mjs` 处理同步，`cloud-ui.mjs` 处理实际表单。

启用云存档时，复制 `.env.example` 为 `.env.local`，使用已有环境的 **Publishable Key** 填写 `VITE_PUBLISHABLE_KEY`。严禁填写管理 API Key、SecretKey 或 service_role 凭据。已有开发机已配置，无需让玩家填写。

`npm run build` 从本机环境变量生成 `dist/cloud-config.json`，并重新构建离线版。`.env.local` 和生成配置均被 Git 忽略；发布在线站点时将生成配置与整个 `dist/` 一同打包。发布产物中的 Publishable Key 是前端可公开的访问入口，读写权限由真实用户会话及数据库控制。没有配置时只关闭云功能，游戏仍可运行。

离线 `download.html` 标记 `data-offline="true"`，不包含 SDK 或访问密钥，不发起账号请求，保留全部离线玩法、本机存档与迁移码。

## 验证范围

已通过真实 CloudBase Node SDK 登录两个临时测试账号，验证 14 项云端行为：写入/读回、丢回包重试、非法数据拒绝、禁止直接更新与内部 RPC、并发版本冲突、用户隔离、切换账号保护、第二个账号独立存档、重新登录恢复。通过管理查询读回实际存档，测试账号与测试行在验收后删除。

另用临时账号验证 6 项账号密码与管理员重置流程：账号登录、建立云存档、管理员重置、旧密码失效、新密码登录后 UID 不变、原云存档仍可读取；测试账号及存档验收后清理。两个线上域名的 API 跨域响应也已核对，未登录请求仍被拒绝。

本地检查覆盖网络延迟中的新增进度、断网恢复、备份、冲突选择、局内禁止替换、退出登录、SDK 会话守卫、用户名/邮箱密码登录、注册验证码回调与表单事件。DOM 适配器不等同于真实浏览器。

当前会话缺少 `cua_repl.js` 浏览器控制工具，因此尚未完成真实浏览器/手机布局验收；也未向真实邮箱发送测试邮件。邮箱 provider 与平台邮件通道已配置为开启，邮件实际可达性需用玩家自己的邮箱实测。多人在线对战尚未实现。
