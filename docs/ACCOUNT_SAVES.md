# 账号与云存档后续方案

当前版本只有浏览器本机存档和 `HA2:` 永久进度迁移码，尚未接入账号、云数据库或账号服务。原站和 GitHub Pages 都是静态前端；它们可以连接同一套后端，使同一账号跨网址、跨设备读取进度。

## 建议的玩家流程

直接以游客身份游玩，需要同步时再绑定邮箱等登录方式。绑定后把已有章节、解锁、纪录和永久修行关联到该账号；联网时同步，断网时仍可使用本机存档，迁移码作为手动备份。

国内玩家优先时可评估腾讯 CloudBase 的身份认证与数据库。它支持匿名身份后续关联正式登录方式。Supabase Auth 也支持匿名用户关联邮箱或其他身份，适合另一种托管选择。正式接入前需开通属于维护者的后端项目，并验证目标玩家网络、登录邮件和套餐额度。

- [CloudBase 身份认证](https://docs.cloudbase.net/authentication-v2/auth/introduce)
- [CloudBase 当前定价](https://cloudbase.net/pricing)：免费体验并非永久无限额套餐。
- [Supabase 匿名身份与关联](https://supabase.com/docs/guides/auth/auth-anonymous)
- [Supabase 当前套餐](https://supabase.com/pricing)：免费计划有资源和功能限制。

GitHub Pages 和 Sites 仍可继续作为网站入口，账号服务独立部署。没有在本次功能中购买服务或创建云端账号。

## 存档边界

第一步同步永久进度即可；若需要肉鸽断点续玩，应另定义关卡结束时的快照，包括层数、弓术、遗物、生命和随机状态。当前迁移码不包含这些局内状态。

每份云存档关联登录服务验证的用户 ID，并带有修订号；写入时比对修订，防止较旧设备覆盖较新进度。纪录、解锁等可以合并，余烬余额和购买操作要在服务端按同一条记录处理，不能把 `mergeProgress()` 的取最大余额规则直接当作自动云同步协议。

用户密码与登录会话交给身份服务处理。数据库访问规则仅允许用户读取和修改自己的存档；前端只携带该服务允许公开的项目配置，管理凭据留在受信任的服务端。

## 无账号的其他选项

现有迁移码已经能跨网址手动搬运永久进度。还可增加下载／导入 JSON 存档文件，方便把备份放在电脑或个人网盘；这仍是手动备份，不会自动登录或同步。
